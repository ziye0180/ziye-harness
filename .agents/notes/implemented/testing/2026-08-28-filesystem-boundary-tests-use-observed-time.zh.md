# Agent Note: 文件系统边界测试使用实测时间

Status: implemented

[English](2026-08-28-filesystem-boundary-tests-use-observed-time.md) | 中文

## Problem

spill 清理边界测试通过 `utimes` 请求一个精确修改时间，并复用请求值作为 cutoff。文件系统可能量化该请求，或返回一个相邻的亚毫秒值。因此测试可能把一个可观察时间早于 cutoff 的文件描述为相等边界，使正确的“只删除严格更早文件”比较删除该文件。

## Decision

设置文件时间后，边界测试读取持久化的 `mtimeMs`，并将这个精确实测值作为清理 cutoff。生产比较仍为 `mtimeMs >= cutoffMs`：相等时间会保留，只有观察到的更早时间才过期。

## Alternatives considered

**在生产代码中舍入时间或增加容差。** 这会为了适应测试设置错误而改变真正较早文件的保留行为。

**使用接近但不相等的时间戳。** 这会测试新鲜文件场景，而不是测试名称所声明的严格相等边界。

**在受影响的文件系统上跳过断言。** 清理规则与平台无关，而且读取已保存时间即可直接测试。

## Verification

边界测试的十六路并发运行全部通过。将生产比较从 `>=` 变为 `>` 会删除边界文件，并让同一断言失败。

## Consequences

测试针对实现实际读取的时间戳证明清理比较，不受文件系统时间表示影响。它明确不测试 `utimes` 是否能精确保留任意请求的浮点数值。
